# DeployMate website

Plain static files — no framework, no build step to view it. Design direction "the
fleet board": the page uses the dashboard's own tokens and shows the real dashboard.

```
index.html            the landing page (hero board + deploy log are native HTML/JS)
docs/                 quickstart, concepts, agents   ← generated by tools/build_docs.py
tour/                 static snapshots of the REAL dashboard on fictional data
assets/               site.css, site.js, fonts (same files as the dashboard), favicon, og.png
tools/                capture.py (tour), build_docs.py (docs), og.html (social image)
Dockerfile, nginx.conf   how it is served (also how DeployMate can host it)
```

## Preview

```sh
cd site && python3 -m http.server 8098        # http://127.0.0.1:8098
```

## Refresh the tour (after the dashboard changes)

```sh
export DEPLOYMATE_DATA_DIR=/tmp/dm-demo        # must be empty
deploymate seed-demo
DEPLOYMATE_DISABLE_MONITOR=1 DEPLOYMATE_ADDR=127.0.0.1:8099 deploymate serve &
python3 site/tools/capture.py http://127.0.0.1:8099
```

The snapshots are the dashboard's real markup and CSS on made-up data
(`internal/demo`): safe to publish, and they stay truthful because they are
regenerated from the product, not drawn.

## Edit the docs

Edit the bodies in `tools/build_docs.py`, then `python3 site/tools/build_docs.py`.
`tools/workflow.example.yml` is the output of `internal/githubci.Workflow`.

## Social image

`tools/og.html` rendered at 1200×630:
`chrome --headless=new --window-size=1200,630 --screenshot=assets/og.png http://127.0.0.1:8098/tools/og.html`

## Before it goes public

- Tag a release (`git tag v0.1.0 && git push origin v0.1.0`): the install command on
  the page downloads from GitHub releases, which don't exist until then.
- Set the real domain in `index.html` (`og:image` should be an absolute URL).
- Every claim on the page is something that ships today; keep it that way — update
  "Not yet" when that changes, and re-check the numbers (e.g. `5 stages`, `1–5 replicas`).
