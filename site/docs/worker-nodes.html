Operate

Run a project on another machine

A small server doesn't have to run everything. Add another computer, yours or a friend's, as a worker node, and run a whole project on it: its apps and its databases together. DeployMate still builds, routes and monitors from your server; the containers run on the node.

A node sees everything that runs on itIts owner can read the code, environment variables and data of what you place there. Only add machines whose owner you trust.

1. Prepare the machine

  • Install Docker and Tailscale, signed in to the same tailnet as your server.
  • Create a user that may use Docker (in the docker group) and can be reached over SSH.

2. Add it in DeployMate

  1. Open Nodes in the sidebar and press Create this server's key. Add the public key it shows to that user's ~/.ssh/authorized_keys on the machine.
  2. Enter a name and the machine's Tailscale address, such as ssh://habib@100.64.0.5, then Add node. If you reach the machine through an SSH alias or a tunnel instead, also fill in address for its ports: the private address its apps will be reached at. DeployMate checks it straight away and shows its CPUs, memory and Docker version, or the reason it can't connect.

A node is checked every minute. It shows offline after three failed checks in a row. Drain stops anything new from being placed on it, use it before you need the machine yourself.

3. Choose where a project runs

On a project's page, under Where it runs, pick the node. Do this before adding anything: a project that already has a database or a deploy stays where it is, because its apps and databases must share one machine's network. To use a node for existing work, create a new project on it.

From then on, deploys, databases, logs, metrics, backups and restarts of that project work as usual and happen on the node. The preview address and your domains reach it through your server.

Good to know

  • Images are copied. The build runs on your server (or on a build machine) and the image is sent to the node. A multi-gigabyte image takes a while over a home connection.
  • Ports stay private. What an app publishes on the node is bound to the node's Tailscale address, not to its public interface.
  • A drained or offline node blocks deploys to it, including redeploying something that already runs there. Nothing falls back to your server.
  • Not yet: moving a project between machines, GPU scheduling, spreading one project over several machines, and picking a node automatically.
