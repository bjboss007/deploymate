Prebuilt: a GitHub Actions workflow builds the JAR; DeployMate downloads and runs it. Pushes to main deploy once the workflow finishes — tick Workflow runs in the repo's webhook settings (the push event can stay on; it is ignored for prebuilt apps).

Deploy mode

Prebuilt mode keeps big builds off this server: your repo's GitHub Actions workflow builds the JAR, and DeployMate downloads and runs it. Use a fine-grained token limited to only this repository with Actions: read-only (for an organization's repo, set the organization as resource owner; an owner may need to approve it). The token is stored encrypted and never shown again. Build mode (default) is unchanged.

Workflow file

Commit this as .github/workflows/deploymate.yml in the repo (Gradle shown; for a multi-module build use your app module's task, e.g. :app:bootJar). It uploads exactly one JAR as a one-day artifact.

Gradle
name: DeployMate build
on:
  push:
    branches: ["main"]
  workflow_dispatch:
permissions:
  contents: read
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with: { distribution: temurin, java-version: "21", cache: gradle }
      - run: ./gradlew bootJar --no-daemon
      - run: mkdir out && cp "$(ls build/libs/*.jar | grep -v -- -plain | head -n1)" out/app.jar
      - run: cp deploymate.yml deploymate.*.yml out/ 2>/dev/null || true
      - uses: actions/upload-artifact@v4
        with:
          name: "deploymate-app"
          path: out/
          retention-days: 1
          if-no-files-found: error

Scaling

How many copies run, and what counts as healthy.

Replicas

One address, up to 5 identical containers behind it: the load balancer skips replicas failing the health path /, and deploys roll one replica at a time so at least one always serves. The health path must answer 2xx/3xx on every replica — Traefik removes replicas that don't (saving checks it now; Traefik picks it up on the next deploy). Limits are per replica — total ask 1024 MB · 1 CPU.

Environment

Which environment this app belongs to.

Environment

Which environment this app runs in (new apps start in dev). Each environment resolves its own services (dev apps get dev-postgres, staging apps get staging-postgres, production apps get postgres) and can use a deploymate.{env}.yml overlay in the repo. One container per app — switching is instant, the next deploy applies it.
