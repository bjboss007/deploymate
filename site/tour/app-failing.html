Add the deploy key to your repo (read-only access), then configure the webhook to push events. Every push to main builds and deploys automatically.

Deploy mode

Prebuilt mode keeps big builds off this server: your repo's GitHub Actions workflow builds the JAR, and DeployMate downloads and runs it. Use a fine-grained token limited to only this repository with Actions: read-only (for an organization's repo, set the organization as resource owner; an owner may need to approve it). The token is stored encrypted and never shown again. Build mode (default) is unchanged.

Build

Where in the repository this app lives. Leave it empty when the app is at the root; set it for a monorepo or a subfolder (the Dockerfile, version files and deploymate.yml are read from there).

Builds use Railpack — the runtime is installed automatically and your repo's version files (.node-version, .python-version, mise config) win unless you pin a version here.

Domains & access

How people reach this app.

App port

The port your app listens on inside its container. DeployMate sends visitors and its health checks there, so a wrong port makes a deploy fail with "connection reset". nginx and static sites use 80; Node and Python apps usually 3000, 8000 or 8080. Applies on the next deploy.

Scaling

How many copies run, and what counts as healthy.

Replicas

One address, up to 5 identical containers behind it: the load balancer skips replicas failing the health path /, and deploys roll one replica at a time so at least one always serves. The health path must answer 2xx/3xx on every replica — Traefik removes replicas that don't (saving checks it now; Traefik picks it up on the next deploy).

Environment

Which environment this app belongs to.

Environment

Which environment this app runs in (new apps start in dev). Each environment resolves its own services (dev apps get dev-postgres, staging apps get staging-postgres, production apps get postgres) and can use a deploymate.{env}.yml overlay in the repo. One container per app — switching is instant, the next deploy applies it.
