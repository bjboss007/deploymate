# Troubleshooting — every issue we hit building this (and its fix)

Each entry has the **symptom**, the **root cause**, and the **fix** so the
next person spends minutes, not hours.

## Build & toolchain

**`go get`: "malformed module path … missing dot in first path element"**
→ import said `pressly/goose/v3` without the `github.com/` prefix. Goose is
`github.com/pressly/goose/v3`.

**`no required module provides package github.com/docker/docker/api/...`**
→ the post-v28 Docker SDK split into `github.com/moby/moby` modules. The
project pins `github.com/docker/docker@v28.5.2+incompatible` (ADR 0012).
Do not `go get -u` the SDK without re-testing keys/stats/pull paths.

**`templ: command not found`** → it's at `$(go env GOPATH)/bin/templ`.
Use `make gen`.

**`go mod tidy` tries to fetch our own module from GitHub** → `templ
generate` hadn't run yet, so `web/templates` had no Go files. Generate
first, tidy second.

**Generated key rejected: `ssh-keygen -y`: "invalid format"`** →
`x/crypto/ssh.MarshalPrivateKey` produced a key its own ecosystem
rejected. Deploy keys are generated by the `ssh-keygen` CLI now
(ADR 0005).

## Docker integration

**`Cannot connect to the Docker daemon at unix:///var/run/docker.sock`**
on macOS → Docker Desktop's socket is `~/.docker/run/docker.sock` and the
SDK doesn't read docker contexts. `runtime.NewDocker` walks candidate
endpoints; set `DOCKER_HOST` to force one.

**Deploy fails instantly with "pull access denied … repository does not
exist" for an image that exists locally** → the daemon's pull endpoint
always hits the registry. Call `HasImage` before `PullImage`
(ADR 0012) — done in both deploy paths.

**CPU charts always 0%** → stats response omitted `percpu_usage` (Docker
Desktop). Use `online_cpus` with `len(percpu_usage)` as fallback
(ADR 0012). Verify with `docker exec -d <ctr> dd if=/dev/zero of=/dev/null`
and expect ~100%.

**Traefik container can't start locally: "error while creating mount
source path … docker.sock"** → Docker Desktop cannot mount its own socket
into containers. Router/cert testing happens on the server; locally
verify the label contract with `docker inspect` (ADR 0004).

## SQLite / store

**`constraint failed: FOREIGN KEY constraint failed`** on app insert with
no obvious bad FK → inserting `""` into a nullable FK column. Convert to
`NULL` (`any(nil)`-style handling in `CreateApp`).

**`sql: Scan error … converting NULL to string is unsupported`** → NULL
scanned into `string`. Scan into `sql.NullString`.

**`no such column: id` from a "last N ordered oldest-first" query** → the
subquery projected away `id` but the outer `ORDER BY id` referenced it.
Keep `id` in the subquery projection (see `ListMetrics`).

## Databases & services

**`pq: SSL is not enabled on the server`** in a deployed app → managed
Postgres has no TLS and lib/pq defaults to `sslmode=require`. Injected
URLs carry `?sslmode=disable` (internal network, ADR 0010).

**`password authentication failed` right after re-provisioning a
service** → the DeployMate DB was reset but the data volume survived.
Postgres/MySQL only apply credentials at initdb; the volume is the
source of truth. Fix by resetting the volume too, or `ALTER USER` inside
the container (see database.md).

**Service "did not become ready within 60s"** → readiness probes exec
inside the container (`pg_isready`, `mysqladmin ping`, `redis-cli ping`);
check `docker logs dm-svc-<slug>` — initdb on a fresh volume is slow, or
the volume has divergent credentials.

## Server / operations

**`address already in use` on 8090 in dev** → a previous `deploymate
serve` survived its shell (`TaskStop` kills the wrapper, not always the
process). `lsof -tiTCP:8090 -sTCP:LISTEN | xargs kill`.

**Push rejected: "Please make sure you have the correct access rights"**
→ SSH keys on the machine belong to a different GitHub account than the
repo owner; `gh auth switch` does not switch SSH keys. Use the HTTPS
remote with gh's credential helper (`git remote set-url origin
https://github.com/<owner>/<repo>.git`).

**Webhook deploys don't happen** → check in order: HMAC signature
(401 = wrong secret), `X-GitHub-Delivery` seen before (dedup, 24 h),
branch name mismatch (must equal `default_branch`, reply says
"ignored"), no app linked to the source (worker log warns).

**Deployment stuck `building` forever** → fixed by the startup reaper:
the worker now fails stale `building` rows on boot. If you see one,
redeploy — or restart if it predates the reaper.

**Docker Desktop: MySQL fails to initialize — "Initialization of the
server's UUID failed" / "No space left on device"** → the Docker Desktop
virtual disk is full (build caches + toolchain images). Fix:
`docker exec dm-buildkit buildctl prune --all`, `docker system prune -f`,
`docker builder prune -f`, `docker volume prune -f`. Wipe the service's
volume and re-provision after (see database.md).

**Container has `HostConfig.PortBindings` but `docker port` shows
nothing** → Docker Desktop's image store only materializes bindings for
ports present in the container's `ExposedPorts`. The docker CLI always
adds them from `-p`, so SDK users must set
`container.Config.ExposedPorts` explicitly — done in
`internal/runtime/docker.go`. Also: passing `NetworkingConfig` to
ContainerCreate silently drops PortBindings — network goes in
`HostConfig.NetworkMode` ONLY.

**Railpack java build fails: `JAVA_HOME is not defined correctly`** →
the repo ships the old Apache `mvnw` wrapper (pre-maven-wrapper 3.2)
which demands JAVA_HOME; Railpack exposes java via mise PATH shims only.
DeployMate removes `mvnw`/`.mvn` from the throwaway checkout for java
builds so the platform's managed Maven is used (`internal/builder/railpack.go`).
